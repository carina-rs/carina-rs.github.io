state

State management commands for inspecting, modifying, and maintaining the Carina state file.

Usage

carina state <SUBCOMMAND> [OPTIONS]

For project-backed inspection commands, Carina compares the configured backend with carina-backend.lock. While a backend migration is pending, list, show, and lookup print a warning to stderr and read the locked old backend. An explicit --state-url bypasses project backend resolution and reads exactly the supplied URL.

Subcommands

list

List all managed resources from the state file.

carina state list [OPTIONS] [PATH]

Output shows provider, resource type, and binding (or resource identity when there is no binding) for each resource:

aws.s3.Bucket my_bucket
aws.ec2.Vpc main_vpc
aws.ec2.Subnet public_subnet

Rows whose state is not a plain applied resource carry a marker: (no current instance), (missing provider identifier), (create in flight since <time>), or (deposed <key> <identifier>) for a pre-replacement instance pending delete.

Prints “No resources in state.” if the state is empty.

Flags

FlagDescription
--state-url <URL>Read state directly from a URL (s3://bucket/key, file://path, or a bare local path), bypassing .crn / backend resolution. Mutually exclusive with PATH

show

Show all managed resources with full attributes.

carina state show [OPTIONS] [PATH]

Output groups attributes under each resource:

# aws.s3.Bucket (my_bucket)
  bucket = 'my-bucket-name'

Human-readable output shows canonical enums as their provider API strings and restores user map keys exactly as authored, including keys that start with $.

Flags

FlagDescription
--state-url <URL>Read state directly from a URL, bypassing .crn / backend resolution. Mutually exclusive with PATH
--tuiDisplay state in interactive TUI mode
--jsonOutput the versioned public JSON document described below

JSON output schema v1

state show --json returns a public inspection document that is independent of the on-disk state format:

{
  "schema_version": 1,
  "state": "present",
  "resources": [
    {
      "binding": "vpc",
      "identity": "main-vpc",
      "provider": "awscc",
      "resource_type": "ec2.Vpc",
      "protected": false,
      "current": {
        "kind": "applied",
        "identifier": "vpc-0123456789abcdef0",
        "attributes": {
          "cidr_block": "10.0.0.0/16"
        }
      },
      "deposed": [
        {
          "identifier": "vpc-0fedcba9876543210"
        }
      ]
    }
  ]
}

The top-level fields are:

FieldMeaning
schema_versionVersion of this public JSON contract. Consumers must check it before reading other fields. A version bump indicates an incompatible contract change.
statepresent when a state file was loaded, or absent when the configured backend has no state file.
resourcesResource rows in state order. This is empty when state is absent or when the present state contains no resources.

Each resource object has these fields:

FieldMeaning
bindingDSL binding for the resource, or null for an anonymous resource.
identityStable Carina resource identity stored in state.
providerProvider name, such as awscc.
resource_typeProvider resource type, such as ec2.Vpc.
protectedWhether Carina protects the resource from deletion.
currentCurrent-generation status, identifier, and attributes.
deposedOne object per older replacement generation still pending deletion. Each object contains its provider-side identifier.

The current object has these fields:

FieldMeaning
kindOne of the closed set described below.
identifierProvider-side identifier when one is known, including during an in-flight create; otherwise null.
attributesSorted attribute object containing ordinary JSON values. It is empty for kinds that do not carry current attributes.

The closed current.kind set in schema version 1 is:

KindMeaning
appliedA completed current resource instance with a provider identifier.
noneThe row has no current instance, but may retain deposed generations.
create_in_flightThe provider accepted a create that has not completed.
missing_identifierA legacy or malformed current instance has attributes but no provider identifier.

Strings, numbers, booleans, lists, and maps are emitted as ordinary JSON. Canonical enums use their provider API string. Persisted host encodings and secret digests are never emitted. A secret or accepted write-only value is always replaced by this marker:

{"redacted": true}

User map keys are restored as authored, including keys beginning with $; those keys are ordinary user data, not persisted $enum or $secret host payloads.

When the configured backend has no state file, state show --json exits 0 and prints:

{"schema_version":1,"state":"absent","resources":[]}

Backend, read, migration, and parse failures remain errors and exit non-zero. Non-JSON state show output is unchanged.

lookup

Look up resource attributes from the state file.

carina state lookup [OPTIONS] <QUERY> [PATH]

QUERY can select:

  • <binding_or_name> — a whole resource
  • <binding_or_name>.<attribute> — one current attribute

The query is matched against resource bindings and resource identities, picking the longest one that is a prefix of the query, so a module-prefixed binding such as r.distribution resolves r.distribution.id. On a tie, a binding wins over an identity.

# Get all attributes of a resource
carina state lookup my_bucket

# Get a specific attribute
carina state lookup my_bucket.bucket

Without --json, single attribute values are returned as raw values (no quotes for strings), suitable for shell usage. Human-readable lookup output is unchanged.

With --json, lookup uses the same schema version 1 conversion as state show --json:

  • A whole-resource lookup returns that resource object, beginning with binding and ending with deposed. It does not wrap the object in the top-level document.
  • An attribute lookup returns that value from current.attributes, including the {"redacted": true} marker for a secret or accepted write-only value.
  • A whole-resource lookup of an in-flight create returns the resource object with current.kind set to create_in_flight. Looking up one of its attributes remains an error.

Lookup requires an existing state and a matching resource, so an absent state remains an error. Canonical enums and user map keys use the same decoded forms as state show --json; persisted $enum, $secret, and $$ encodings are never exposed.

Flags

FlagDescription
--state-url <URL>Read state directly from a URL, bypassing .crn / backend resolution. Mutually exclusive with PATH
--jsonAlways output as JSON

state lookup reads resources only; to read values from an exports block, use carina export.

Shell completions are supported for both resource names and attribute names.

refresh

Refresh state from cloud providers without planning or applying. Reads the current state of all managed resources from the providers and updates the state file. Every provider must load before the refresh starts. Progress is shown the same way as for carina apply (see Progress output).

carina state refresh [OPTIONS] [PATH]

Flags

FlagDescription
--lock <BOOL>Enable/disable state locking (default: true)

bucket-delete

Delete the state bucket. This is a destructive operation that removes the bucket and all state history.

carina state bucket-delete [OPTIONS] <BUCKET_NAME> [PATH]

The bucket name must match the bucket attribute in the backend configuration. The configuration and its providers must load successfully; Carina checks this before asking for confirmation. Without --force, Carina prompts for confirmation by requiring the user to type the bucket name.

During a pending backend migration, bucket-delete targets the configured NEW backend, not the OLD backend recorded in carina-backend.lock.

Flags

FlagDescription
--forceForce deletion without confirmation

Related Commands

force-unlock

Force unlock a stuck state lock. This is a top-level command, not a state subcommand.

carina force-unlock <LOCK_ID> [PATH]

Use this when a previous operation was interrupted and left the state locked. The lock ID is shown in the error message when a lock conflict occurs.

State File Format

Carina stores state in carina.state.json (local backend) or in an S3 bucket (remote backend). The state file tracks:

  • lineage — unique identifier for the state, used for drift detection
  • serial — incrementing version number
  • resources — list of managed resources with their provider, type, identity, binding, attributes, and dependency bindings
  • exports — values published by the exports block
  • exports_version — version of the exports encoding, independent of the state format version, so older Carina versions can still read exports from a newer state file

Since state format version 14, Carina reserves single-$ object keys for host payloads. Canonical enums are stored as $enum payloads and redacted secrets as $secret payloads, while user keys beginning with $ are escaped by adding one leading $. Carina decodes that representation when values are shown through public output, exports, or upstream_state. Human-readable state output renders a redacted secret as (secret); schema version 1 JSON uses {"redacted": true}. The persisted representation is an internal storage detail and is not the state show --json contract.
